Herramientas del curso

Flutter + Dart

★ Herramienta principal

Framework de Google, multiplataforma (Android + iOS). Hot reload, documentación excelente y alta demanda laboral. Un solo código para ambas plataformas.

Android Studio
/ VS Code

★ IDE oficial

Android Studio incluye emulador AVD integrado. VS Code + extensión Flutter como alternativa más ligera. Ambos son gratuitos.

GitHub

● Obligatorio

Control de versiones desde el día uno. Cada entregable es un repositorio con historial de commits. También se usará para el plan del curso (GitHub Pages).

Mockup de pantallas

Herramienta libre

Entrega en PDF. Figma, Canva, Marvel, papel escaneado, PowerPoint — lo que el equipo prefiera. Se evalúa el diseño, no la herramienta.

Firebase

Unidad 3

Firestore (base de datos remota en tiempo real) y Firebase Auth para el proyecto final. Plan gratuito (Spark) suficiente para el curso.

IA como copiloto

Con responsabilidad

GitHub Copilot, ChatGPT, Gemini, Claude — permitidos como asistentes. El estudiante sigue siendo el autor. Ver política completa abajo.

Política de IA · Copiloto, no piloto

🤖

El uso de IA está permitido — con responsabilidad

GitHub Copilot, ChatGPT, Gemini, Claude y similares son herramientas válidas de desarrollo. El estudiante sigue siendo el autor y el responsable de todo lo que entrega.

✅ Uso permitido
  • ›Pedir que explique cómo funciona un widget o método
  • ›Sugerir estructura de código que el estudiante ya diseñó
  • ›Depurar un error que ya entendió pero no sabe resolver
  • ›Generar código base que luego se adapta y comprende
  • ›Declarar el uso de IA en el README (suma puntos)
❌ Uso no permitido
  • ›"Hazme la app completa del proyecto final"
  • ›Entregar código que el estudiante no puede explicar
  • ›Un solo commit con todo el proyecto
  • ›No saber por qué el código hace lo que hace
  • ›Todos los equipos con código idéntico
🔍 Cómo se verifica
  • ›Historial de commits en GitHub (mínimo 10 commits)
  • ›Preguntas técnicas en la sustentación
  • ›"¿Por qué usaste este widget y no ese?"
  • ›Modificar una función en vivo durante la demo
  • ›El código debe reflejar el nivel del grupo
💡 Marco conceptual
La IA es un agente colaborador: tú defines el problema, tú tomas las decisiones de arquitectura y tú validas el resultado.

El programador sigue siendo responsable — la IA es como un practicante muy rápido que debes supervisar.
Declarar el uso de IA en el README suma puntos, no los resta.
